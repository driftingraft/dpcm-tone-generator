# なぜDPCMで「音程のある音」を鳴らすのか — このツールの背景と意義

dPCM Tone Generator は「ファミコンのdPCMサンプルを作るツール」ですが、その本当の狙いは
**ファミコンに"6音目"を追加すること**にあります。このドキュメントでは、使い方ではなく
「このツールが使えると何が嬉しいのか」を説明します。

## 3行まとめ

- ファミコンのDPCMチャンネルは、普通は「録音したドラムを鳴らす」ためのものです
- しかし数十バイトの波形を**ループ再生**させると、音程のある「楽器」として使えます
- このツールは、その波形をdPCMの制約に**数学的にぴったり合う形でゼロから合成**します。結果、三角波や矩形波を消費せずに、正確な音程のベースラインを1チャンネル追加できます

## 背景：ファミコン音源の「音数の壁」

ファミコン内蔵音源は5チャンネルです。

| チャンネル | 音色 | よくある役割 |
|---|---|---|
| 矩形波 ×2 | パルス波（4種のデューティ比） | メロディ、ハモリ |
| 三角波 ×1 | 三角波（音量固定） | **ベース**、またはタム・キック |
| ノイズ ×1 | ノイズ | ハイハット、スネア |
| DPCM ×1 | サンプル再生 | ドラム、ボイス |

曲を作るとすぐに気づきますが、メロディ＋ハモリ＋ベース＋ドラムで**5チャンネルは即座に埋まります**。
特に三角波は「ベースに使うか、ドラムの低音に使うか」の取り合いになりがちで、
ここがファミコン作曲のいちばん苦しいところです。

## DPCMチャンネルの通常の使われ方と、その限界

DPCMチャンネルは1ビット差分変調（サンプル値を+2/-2で追いかける方式）で波形メモリを再生する
チャンネルで、通常は録音したドラムやボイスの再生に使われます。

ただし「音程のある楽器」として使うには不向きに見えます。

- 再生レートは**16種類の固定値**しか選べない（連続的なピッチ変更ができない）
- サンプル長は**8+128n サンプル**（1+16n バイト）という飛び飛びの値しか取れない
- 1ビット差分なので急な波形変化に追従できず、量子化ノイズが出る
- 録音物を音階ぶん用意すると、すぐに数十KBのメモリを消費する

## 発想：録音を「再生」するのではなく、1周期の波形を「ループ」させる

DPCMにはループ再生フラグがあります。**波形1周期ぶん（数十〜数百バイト）のサンプルをループさせれば、
DPCMチャンネルはオシレーター（発振器）になります。**
「サンプルレート ÷ 1周期のサンプル数」がそのまま発音周波数になるので、音程も作れます。

このアイデア自体には先行例があります。サンソフトのゲーム（『ギミック!』『バットマン』など）の
迫力あるベースは、DPCMでベース音を鳴らす「サンプリングベース」として有名です。

**このツールの新しさは、録音のかわりに「dPCMの制約にぴったり合う波形」をゼロから数学的に合成する点です。**

## 何が難しいのか（＝このツールが自動化していること）

「1周期をループさせるだけ」と言うのは簡単ですが、実際にやろうとすると制約が絡み合います。

1. **音程の方程式が解けない**
   発音周波数 = レート ÷ 1周期サンプル数。ところがレートは16種類の固定値、
   サンプル総数は8+128nの飛び飛びの値。目的の音程（例: C3 = 130.81Hz）に対して
   「誤差が十分小さい整数の組み合わせ」を探す必要があります。
   → **fitモード**が全レート×周期数の組み合わせを全探索し、セント単位で誤差最小の解を見つけます

2. **ループの境界でクリックノイズが出る**
   波形の終端と先頭の値がずれていると、ループのたびに「プチッ」というノイズが乗ります。
   → **warmup**（エンコーダの状態が定常化するまで助走させて開始値を決定）と
   **auto-start**（開始値を波形に合わせる）で、境界の段差を排除します

3. **1ビット差分の表現力の限界**
   ±2/サンプルでしか動けないため、波形の傾きが急だと追従できません。
   → 高品質モードでのレート選択、音量調整、ローパスフィルタ等でエンコードに適した波形へ整えます

4. **音階ぶん用意すると量が多い**
   30音階を1つずつ手作業で作るのは現実的ではありません。
   → **バッチ生成**が全音階の.dmcとppmck定義ファイルを一括出力します

## 使うと何が嬉しいのか

### 1. 実質「6音目」が手に入る

三角波・矩形波を1本も消費せずに、正確な音程のベースラインを追加できます。
三角波をドラム（キック・タム）に回したり、矩形波2本をフルに和音・メロディへ使えるようになります。

### 2. ファミコンでは本来出せない音色が鳴る

内蔵チャンネルの音色は矩形波と三角波だけですが、この方式なら**ノコギリ波**をはじめ、
サイン波、FDS音源の波形、さらには任意のWAVから切り出した1周期波形まで自由です。
サブオクターブ混合（1オクターブ下を重ねる）で低音に厚みを足すこともできます。

### 3. メモリ消費が驚くほど小さい

ループ再生なので、1音あたり必要なのは波形1周期×数周期ぶんだけです。
さらに**サンソフトベース方式**（同じ.dmcを異なる再生レートで使い回す方式）を使うと、
デフォルト設定ではC2〜F4の30音階を**基本サンプル8個・約1.1KB**でカバーできます
（音階ごとに個別サンプルを持つ場合と比べて約73%の削減）。

### 4. ppmckですぐ使える

生成と同時に`@DPCM`定義ファイルが出力されるので、MMLに貼り付けて
`E n0` と書けばその場で鳴らせます。GUIなら生成した音をブラウザで試聴してから持ち出せます。

## トレードオフも正直に

- DPCMチャンネルをベースに使っている間は、DPCMドラム（サンプリングドラム）と同時発音はできません。
  ドラムはノイズ＋三角波で組む、またはキックの瞬間だけベースを切る、といった工夫は必要です
  （これは実機のサンプリングベース採用曲でも使われてきた定番の手法です）
- 固定レートの制約上、音程には数セント〜十数セントの誤差が残ります（ツールは誤差を表示し、
  許容範囲を指定できます）。また、およそC5より上の高音は誤差が大きくなり実用的ではありません
- DPCM再生中はコントローラ読み取りと競合する既知のハードウェア癖など、実機特有の注意点があります
